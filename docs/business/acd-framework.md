# ACD (Agentic Continuous Delivery) — why it governs this whole project

## The problem

AI agents generate changes faster than a human can review them, lack an organization's implicit norms, and can pass every test while violating the original intent. ACD extends Continuous Delivery by adding constraints and artifacts specific to agent-generated changes. Its core premise: *a change generated by an agent must meet the same quality bar as one generated by a human.*

Original source: https://beyond.minimumcd.org/docs/agentic-cd/

## Why ACD is the foundation, not an optional package

Treating ACD as a separately installable knowledge package, apart from the framework's base rules, creates real redundancy: two slightly different `@constraints` schemas for the same artifact (documented and resolved in `docs/tdrs/feature-constraints-format.md`). In this project, **ACD is the default flow from the first command** — there is no "mode without ACD."

## The 4 delivery contract (ADC) artifacts

| Artifact | Owner | Where it lives in this project |
|---|---|---|
| Intent description | Human | `Feature:` block in the `.feature` — the agent proposes, never rewrites what's confirmed |
| User-visible behavior | Human | BDD scenarios in `docs/features/*.feature` |
| Technical description | Human | TDRs/ADRs referenced in `@constraints.governed_by` |
| Acceptance criteria | Human | Concrete Given/When/Then scenarios, with observable outcome |

## How this looks in this project, specifically

- **`cycle-init`** replaces `acd-spec-cycle` — authorship and evolution unified into a single command that detects the mode. See `docs/tdrs/cycle-commands.md`.
- **`cycle-run`** replaces `acd-session` — atomic sessions of at most 3 scenarios, mechanical close via `cycle-validate` writing a persisted report to disk (`docs/tdrs/cycle-validate-report.md`) — not just prose asserting something happened.
- **`escalation_triggers`** — concrete conditions that, if encountered during implementation, force the agent to stop and ask instead of deciding alone.
- **Separation of concerns** — the agent proposes, critiques, and refines; it never approves its own artifacts or merges them.

## What's still unresolved
